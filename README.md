## Repository Structure

The repository is organized into the following folders and files to ensure modularity and maintainability:

### `src/`

The main source folder for the application. It contains all the code, components, pages, services, and styles used in the project.

#### `components/`

- Contains reusable React components used across the application.
- Examples: `quiz.js`, `quizBoxes.js`, `MainContent.js`.
- Handles UI elements like quiz boxes, navigation, and quiz views.



#### `pages/`

- Contains React components that represent different pages of the application.
- Examples: `welcome.js`, `StudyRoom.js`, `store.js`, `spacedLearningQuiz.js`.
- Each file corresponds to a specific route or feature in the app, such as the study room, store, or spaced repetition quiz.



#### `services/`

- Contains utility functions and services for interacting with external systems like Firebase.
- Examples: `addQuiz.js`, `userSearch.js`, `showPoints.js`.
- Handles database operations, user management, and other backend-related tasks.



#### `styles/`

- Contains CSS files for styling the application.
- Example: `index.css`.
- Defines the look and feel of the app, including layout, colors, and typography.



#### `models/`

- Contains data models or schemas for the application.
- Examples: `quiz.js`, `questions.js`, `db.js`.
- Defines the structure of data like quizzes, questions, and user-related information.



#### `utils/`

- Contains utility functions or helpers used throughout the app.
- Examples: Firebase configuration, reusable functions, etc.
- Example: `unfinishedfirebaseDB.js` contains Firebase initialization and database-related logic.



### Additional Directories



#### `public/`

- Contains static assets and files that are publicly accessible.
- Examples: `index.html`, `favicon.ico`.
- Used for meta tags, app icons, and other static resources.



#### `node_modules/`

- Contains all the dependencies installed via npm or yarn.
- Automatically generated by the package manager based on `package.json`.



#### `.github/`

- Contains GitHub-specific configuration files, such as workflows for CI/CD.
- Example: `deploy.yaml` handles deployment to GitHub Pages.



#### `firebase/`

- Contains Firebase configuration files.
- Examples:
  - `firestore.rules`: Defines security rules for Firestore.
  - `firestore.indexes.json`: Defines Firestore indexes.

## Test subscriptions (Stripe test vs live)

Set **`LOCAL_TESTING`** in the **root** `.env`:
- `LOCAL_TESTING=true` → Stripe **test** keys
- `LOCAL_TESTING=false` → Stripe **live** keys

Restart `npm run dev` after changing it. Redeploy functions (`node scripts/deploy-functions.js`) so the backend uses the same mode.

Keep **Test mode ON** in the Stripe Dashboard when `LOCAL_TESTING=true`. Turn it **OFF** for live.

**Prices must be Recurring** (not one-time): **Monthly** and **Yearly** on the same product. Checkout uses `mode: 'subscription'`; the interval comes from the Price. Profile shows **Monthly** / **Yearly** and **Renews on …** from Stripe.

1. **Keys and price**
  - [API keys](https://dashboard.stripe.com/test/apikeys): copy `pk_test_…` and `sk_test_…`
  - [Products](https://dashboard.stripe.com/test/products): create one **recurring monthly** product/price and copy the **Price ID** (`price_…`, not `prod_…`)
  - Root `.env` (with `LOCAL_TESTING`):
    - Test: `REACT_APP_STRIPE_TEST_PUBLISHABLE_KEY`, `REACT_APP_STRIPE_TEST_PRICE_ID`, `REACT_APP_STRIPE_TEST_YEARLY_PRICE_ID`
    - Live: `REACT_APP_STRIPE_LIVE_PUBLISHABLE_KEY`, `REACT_APP_STRIPE_LIVE_PRICE_ID`, `REACT_APP_STRIPE_LIVE_YEARLY_PRICE_ID`
  - `quirkle-functions/.env`: matching `STRIPE_TEST_*` / `STRIPE_LIVE_*` secret, webhook, monthly and yearly Price IDs
2. **Backend**
   - **Redeploy Cloud Functions** (from the **repo root**, after `quirkle-functions/.env` has live/test secrets):
     ```bash
     firebase login
     firebase use quirkle-db
     node scripts/deploy-functions.js
     ```
     This copies `quirkle-functions` to `~/.cache` first. A plain `firebase deploy --only functions` often times out because this repo is on Desktop/iCloud.
     This **updates** the existing functions (`createCheckoutSession`, `createPortalSession`, `confirmCheckoutSession`, `stripeWebhook`, `adminCancelSubscription`, `getSubscriptionDetails`, `cancelSubscription`). It does not create duplicates.
     Production URLs:
     `https://us-central1-quirkle-db.cloudfunctions.net/createCheckoutSession`
     `https://us-central1-quirkle-db.cloudfunctions.net/createPortalSession`
     `https://us-central1-quirkle-db.cloudfunctions.net/stripeWebhook`
     `https://us-central1-quirkle-db.cloudfunctions.net/adminCancelSubscription`
     `https://us-central1-quirkle-db.cloudfunctions.net/getSubscriptionDetails`
     `https://us-central1-quirkle-db.cloudfunctions.net/cancelSubscription`

     Leave `REACT_APP_CLOUD_FUNCTIONS_URL` unset in the app `.env` so the app hits those deployed URLs.

   - **Or run the emulator** instead of deploying:
     ```bash
     firebase emulators:start --only functions
     ```
     Then set in root `.env`:
     `REACT_APP_CLOUD_FUNCTIONS_URL=http://localhost:5001/quirkle-db/us-central1`
3. **Webhooks**
   - **If you deployed** (you already did): in [Stripe Webhooks](https://dashboard.stripe.com/test/webhooks) add endpoint
     `https://us-central1-quirkle-db.cloudfunctions.net/stripeWebhook`
     Events: `checkout.session.completed`, `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.payment_succeeded`, `invoice.payment_failed`.
     Copy the signing secret (`whsec_…`) into `quirkle-functions/.env` as `STRIPE_WEBHOOK_SECRET`, then run `node scripts/deploy-functions.js` once more so the secret is on the server.

   - **Only if using the emulator** (not needed after a successful deploy):
     ```bash
     stripe listen --forward-to http://localhost:5001/quirkle-db/us-central1/stripeWebhook
     ```
     Put the printed `whsec_…` into `quirkle-functions/.env` as `STRIPE_WEBHOOK_SECRET`.
4. **App checks**
  - Sign in → **Profile** → **Subscribe monthly** or **Subscribe yearly**
  - Pay with test card `4242 4242 4242 4242` (any future expiry, any CVC)
  - In Firestore, `users/{email}/userSetting/settings` → `"subscription status"` should become `subscribed`
  - Free: creating a 7th deck is blocked
  - Subscribed: unlimited decks; still 200 questions per deck
  - **Manage billing** opens the Stripe Customer Portal
  - Subscribed Profile shows **Renews on …** (or **Ends on …** if canceled at period end), from Stripe
  - **Cancel subscription** on Profile sets Stripe `cancel_at_period_end` (no renew); plan stays Subscribed until the period ends, then webhook sets Free

5. **Admin: set a user back to Free**
   - Sign in as an admin → **Admin**
   - Find the user → **Set to free** (confirms first)
   - This cancels their Stripe subscription and writes `"subscription status": "free"` on `users/{email}/userSetting/settings`
   - Requires the `adminCancelSubscription` function to be **publicly invokable** (Firebase Auth is still checked inside the function). After deploy, if Set to free does nothing, run:
     ```bash
     gcloud functions add-iam-policy-binding adminCancelSubscription --region=us-central1 --member=allUsers --role=roles/cloudfunctions.invoker --project=quirkle-db
     ```
